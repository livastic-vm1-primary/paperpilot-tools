The problem and the actual deliverable

Two independent payment-client processes could both try to reclaim a dead wallet lock by reading, comparing and removing the same stale record. Under a specific interleaving, a later waiter could delete the first waiter's newly acquired live lock. In a payment client, that can make duplicate attempts possible when recovery logic is unsafe.

The fix adds an exclusive, nonexpiring stale-reaper gate created with the filesystem's wx mode around only the re-read / comparison / unlink critical section. A waiter that sees an existing gate does not remove or age it out; it waits to the original bound and exits without signing or buying. An abandoned gate must be inspected and removed manually only after confirming no process still owns it. The design chooses refusing a payment over guessing that it is safe to retry.

The maintainer's accepted review documents a deterministic failure on the unmodified parent and passing regression tests after the patch. His Node.js 24 test run: 187 tests total, 182 passed, 0 failed, 5 environment skips. Test results prove the local race properties, not universal network idempotency or settlement correctness.
